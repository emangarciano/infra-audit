# Define the administrative summary and movement history

Type: grilling
Status: resolved

## Question

Which fields should administrative staff see in the queue, transaction summary, and movement history? Walk through a suspension with item-level remarks and a completion with a certified amount. Specify the summary and event metadata that staff need for intake and resubmission while keeping detailed audit data within audit roles. See §4.2, FR-02, FR-07, and AC-02.

## Answer

- Show administrative staff the project title/reference, transaction type and short reference/title, assigned auditor, current status, and latest action date. Show the received or created date on the transaction summary.
- Show registration, suspension, resubmission, audit resumption, completion, and duplicate voiding in movement history. Include the actor who recorded each movement, actual action date, recording timestamp, and previous and new status where applicable.
- Restrict optional contract details, transaction notes, detailed checklist and corrections, event remarks and reasons, slip contents and printing, certified amounts, and completion justifications to auditors and supervisors. Enforce access on the server for every read, including direct requests for detailed records and slips.

For AC-02, verify that administrative staff can find the same transaction and read its status movements. Verify that checklist and slip requests require an audit role. Use a suspension with item remarks and a completed transaction with a certified amount to check that the administrative response contains only the approved fields.
