# Domain docs

This repo uses a single-context layout. Before exploring a topic, read the root `GLOSSARY.md` and the relevant architecture decision records in `docs/adr/`, when present.

Use glossary terms in issues, proposals, and tests. Bring terminology gaps to `domain-modeling`. Create glossary entries and decision records as terms and decisions are agreed.

If a proposal conflicts with a decision record, cite the record and explain why the decision should be revisited.
